# Своя тема через dsbuilder

Как получить пакет темы из токенов дизайн-системы.

## Что генерируется

Тема — это сгенерированный SwiftPM-пакет, и он **двухуровневый**:

- **токены** (`Tokens/`, `Fonts/`, `Theme.swift`) зависят только от `SDDSThemeCore`,
  поэтому их можно поставлять отдельно от библиотеки компонентов;
- **appearance-вариации** компонентов тянут ``SDDSComponents`` и `SDDSIcons`.

Сгенерированный код коммитится в репозиторий, поэтому потребителю тулчейн не нужен. Править
`Themes/*` руками нельзя — следующая генерация затрёт правки.

## Генерация

CLI собирается из каталога `DesignSystemBuilder`:

```sh
cd DesignSystemBuilder && ./build_cli.sh
./build/dsbuilder/dsbuilder
```

Источник токенов — каталог `.sdds/`, который наполняет внешний Kotlin/Native CLI того же
имени (обёртка `scripts/fetch_sdds.sh`). При пустой `.sdds/` наш CLI откатывается на
zip-снапшот схемы.

## Автономный бандл

Режим `--standalone` собирает тему в плоскую папку `.swift`, которая компилируется одним
модулем без линковки наших библиотек. Исходники можно забрать прямо с релиза, не имея
чекаута репозитория:

```sh
./dsbuilder ./config.json --standalone --components --sources-version <tag>
```

## Откуда берётся состав свойств

Кодогенерация управляется метаданными: `Tools/SDDSApiInfoGenerator` обходит
``SDDSComponents`` через SwiftSyntax и снимает слепок публичного API всех `*Appearance` в
`ios-api-meta.json`. Поэтому новое свойство компонента появляется во всех темах сразу после
регенерации меты, а не переписывается руками для каждой.

Разметка свойств живёт в самой библиотеке настоящими Swift-атрибутами (`@ApiName`,
`@ApiValue` и другими) из пакета `SDDSApiInfo` — опечатка в маркере ломает компиляцию, а не
теряется молча.
