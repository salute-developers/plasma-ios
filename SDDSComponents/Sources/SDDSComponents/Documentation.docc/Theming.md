# Темизация

Как компонент получает свой внешний вид и что можно менять.

## Appearance вместо модификаторов

У каждого компонента есть структура `*Appearance` — ``SDDSComponents`` не предлагает
привычных SwiftUI-модификаторов вроде `.foregroundColor`. Все цвета, типографика, отступы и
формы приходят из темы одним значением:

```swift
BasicButton(
    title: "Label",
    subtitle: "",
    appearance: SDDSServTheme.BasicButton.l.accent.appearance,
    layoutMode: .wrapContent,
    action: {}
)
```

## Цепочка вариаций

Цепочка читается как «размер → стиль»:

- **размер** — `.xxs`, `.xs`, `.s`, `.m`, `.l`, `.xl`;
- **стиль** — `.default`, `.accent`, `.secondary`, `.positive`, `.negative`, `.warning`,
  `.clear`, `.dark`, `.black`, `.white`.

Набор у каждой темы свой: например, у `PlasmaHomeDSTheme` нет `black`, `positive` и `white`.
Точный список — в `Themes/<Name>Theme/BasicButton/BasicButton+Variations.swift`.

Вариации сравниваются и хешируются **только по имени**: две вариации с одинаковым `name`
равны, даже если их `appearance` различаются. См. ``AppearanceVariation``.

## Значения по умолчанию

Если `appearance` не передан, компонент читает значение из `EnvironmentValueProvider` —
реестра, который заполняет `Theme.initialize()`. Это удобно, когда весь экран должен
следовать теме без стилизации на каждом вызове.

## Состояния

Часть значений зависит от состояния компонента: нажат, выбран, отключён. За это отвечает
`StatefulValue` из `SDDSThemeCore`. Значение подбирается по первому элементу, чьё множество
состояний является подмножеством активных, поэтому **элемент без состояний перехватывает
любое обращение** — если он стоит первым в списке.

Порядок отката: явный fallback → `defaultValue` → безусловный элемент → первый элемент.

## Сабтемы и тенанты

Сабтема (`Subtheme`) переключает набор токенов под фон — например `.onDark`. Тенант — это
полноценный дополнительный набор токенов, накладываемый на базовую тему в рантайме;
активируется через `Theme.initialize(tenant:)`.
